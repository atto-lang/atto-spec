# Actor DATA codec selection v1 — draft proposal

Status: DESIGN_ONLY_NOT_EXECUTED. This extends existing Sendable/Serializable and sealed DATA/CONTROL contracts; it does not introduce a replacement wire protocol or claim compiler support.

## Selection and type contract
- Keep local Sendable proof separate from Serializable[Format] and schema qualification. Preserve existing borrow-checked share, move and checked copy paths; require codec only on serialized DATA, or when explicitly configured to force serialization. No raw references, host objects, codec instances, mutable closures or authority-bearing control values in DATA.
- Preserve existing canonical MessagePack v2 and native/WASM DATA v0 compatibility; MessagePack is the proposed default for new serialized actor DATA endpoints. Protobuf and CBOR are first-class selectable profiles; FlatBuffers is optional and gated on immutable verified buffers. No silent wire-version changes.
- Application defaults, supervisor policy and per-actor/endpoint choice are proposed configuration scopes. Sender must use a mutually authorized codec/schema/version tuple; endpoint registration chooses from supervisor allowlist; children may narrow but never widen limits or capabilities. Explicit unavailable or incompatible codec fails closed; no auto-sniff, downgrade, fallback or implicit transcode. Syntax and stable ID allocation require spec review; no grammar change in this draft.
- ActorMessageCodec[T] remains separate from NetworkCodec[T]; encode borrows input and produces owned bounded bytes; decode yields owned T or typed error, never arbitrary instantiation or reflection. Compile-time schema-derived codecs, AOT-safe registry; no dynamic plugin loading on untrusted input. Shared portable logic belongs in atto-common-source and atto-serialization-and-validation where possible.
- Stable nominal type/variant IDs, field tags, integer widths, UTF-8, Option/Result, tuple and bigint mapping must be specified per format; unsupported shapes reject at compile time or admission. Protobuf schema evolution reserves removed tags; explicit presence and unknown field policies; reject ambiguous duplicates in strict actor profile. CBOR deterministic profile and tag allowlist; no indefinite lengths initially. FlatBuffers validate every offset/vector, cap depth and work, keep bytes immutable until final release. MessagePack retain existing canonical rules and extension allowlist. Define float/NaN, map key and unknown variant policy before new profiles ship.

## Security invariants (mandatory for every transport)
- Supervisor CONTROL (panic, restart, stop, lifecycle) stays runtime-issued and separate; codec selection applies only to DATA. Wire data cannot manufacture ActorRef, CONTROL or capabilities; resolve logical IDs through authenticated registry/capability checks, tenant and generation fences. Validate authenticated sender, recipient, schema identity and codec/version against endpoint policy. Network envelope and payload integrity bind together with authenticated transport (e.g. TLS 1.3 with peer identity), anti-replay where needed; no untrusted metadata authorizes privileges.
- Check frame length and reserve bounded bytes/credits before allocations. Enforce wire bytes, expanded bytes/nodes, nesting, collection lengths, UTF-8, checked arithmetic, parser work/fuel, per-tenant and per-mailbox quotas; charge concurrent decode work; reject trailing bytes, invalid types, disallowed tags/extensions and duplicate keys/fields according to strict profile. Compression off by default; opt-in requires independent compressed/expanded/work ceilings. No unsafe object deserialization or reflection.
- Admission and publication transactional: revalidate generation and authorization before enqueue; failed decode, cancellation, restart, queue-full and race release exactly once all credits and temporary allocations; no partial publication, no leaked payloads, no cross-tenant alias. Failures produce typed bounded/redacted diagnostics.
- Proposed starting maxima (not normative until review): 1 MiB frame, 8 MiB decoded allocation, depth 32, 65,536 elements, 256 KiB string, 16 MiB mailbox bytes, 4,096 messages; global/per-tenant work limits and actual backend capability profiles mandatory.
