# Class field visibility v1 — `private`, `pub[pkg]`, `pub`

**Status:** User-approved target syntax (2026-11-18). Normative for AttoLang class-field declarations; backend coverage must be verified independently. The Rust/Wasm compiler currently builds a single source package and does **not** prove cross-package linking or access-control isolation.

## Syntax and canonical spelling

```ebnf
class_field_visibility = "private" | "pub" "[" "pkg" "]" | "pub" | ε ;
class_field_decl = [class_field_visibility], class_field_binding ;
```

Visibility appears before the field's optional `let`, `val`, `final` or `const` modifier and its type. For this version **`pub[pkg]` is canonical**, not `pub(pkg)`. Reject unknown scope arguments (`pub[friend]`, `pub[module]`), malformed brackets, duplicate/contradictory modifiers, and `private[pkg]`. Do not reinterpret the bracket contents as an array access, generic argument, or runtime expression.

```atto
define pub class Vault as
    int secret = 1;             // implicit private, implicit val
    private int pin = 2;       // explicit private
    pub[pkg] int id = 3;       // same-package access
    pub string name = "vault"; // publicly accessible
    pub[pkg] let int count = 0; // package-visible mutable field
    pub final int revision = 1;
end
```

This is class-field syntax, **not** a blanket authorization for scoped methods, actors, constructors, or top-level declarations. Future scopes such as `pub[module]` are reserved for a separate decision. Ordinary `pub` continues to mean unrestricted public access subject to visibility of the enclosing type.

## Access contract

| Declared modifier | Access from declaring class | Other classes in same package | Different packages |
| --- | --- | --- | --- |
| omitted / `private` | yes | no | no |
| `pub[pkg]` | yes | yes | no |
| `pub` | yes | yes | yes, provided enclosing type and imports allow access |

- Packages are resolved by the compiler's authenticated package identity, **not** by matching strings, paths, aliases, imported names or module suffixes. Access through an imported type, an inherited field, `use Parent.field as alias`, an extension/receiver method, a generic specialization, FFI or generated code must never bypass the original field's visibility.
- Subclasses in a different package do not gain access to `pub[pkg]` or `private` fields. A public subclass, a public getter generated by the compiler, a re-export, or a field alias must not *silently* promote original storage to public. Explicit user-defined public functions may intentionally expose derived values; the compiler must not synthesize equivalent leaks.
- Field visibility and *mutation* are independent. A public `val` field is not reassignable; a package-visible `let` field still requires normal checked mutable access and borrowing. Deep object mutability and ownership/actor isolation are not inferred from the field's visibility.
- For concise declarations, the target default is implicit `val` for **all types** (both primitive and nonprimitive). `let`, `final` (single assignment), and `const` (constant contract) remain explicit distinct choices. Do not choose mutability from the field type.
- For any source target unable to authenticate two distinct package identities, do not claim to have tested a cross-package case. A single-source/package browser compiler can parse and enforce class-private visibility and access to package fields within its sole package, but cross-package linkage must fail closed until a real linker is available.

## Diagnostics and conformance

Positive: explicit and implicit private fields usable from the declaring class, `pub[pkg]` fields readable from unrelated same-package classes, `pub` fields readable across package boundaries, `pub[pkg] let` mutation subject to ownership checks, and `val`/ `final`/ `const` combinations preserving their underlying semantics.

Negative: explicit and implicit private fields accessed from other classes (including same-package), package fields accessed from a different package (including through imported aliases, inheritance or generated adapters), malformed or unsupported `pub[...]` scope, `pub(pkg)`, duplicate/contradictory visibility, and attempts to widen field visibility by a re-export or specialization.

Required evidence: a parser AST preserving **three distinct states**, checked read and write paths, typed diagnostics with source spans, negative fixtures yielding no executable artifact, bounded inheritance/alias verification, plus executed guest tests on each claimed backend and **real multi-package** conformance once the package linker exists. Host-only syntax and single-source Wasm evidence are not a claim of cross-package safety or backend parity.
