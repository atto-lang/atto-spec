# Native actor retry, rollback, undo and compensation v1

**Status: owner-directed TARGET / NOT_EXECUTED.** This proposal extends [sealed state](../spec/05-actors-and-state.md), [failure effects](../spec/07-errors-and-failure.md) and [persistent actors](../spec/22-persistent-actors-and-storage.md). It does not replace the persistent storage adapter or change supervisor authority. Public syntax and concrete intrinsic ABI remain proposals until compiler/formatter review.

## Semantic boundaries

Retry re-executes an eligible attempt; rollback discards an uncommitted mutation; undo appends a new committed inverse transition; redo appends a new reapplication; compensation is a forward business operation counteracting an observed effect; replay reconstructs committed state without reissuing effects. No universal exactly-once remote execution or physical reversal is promised. Ordinary actors opt into retry and bounded reversible state independently of persistence; persistent actors additionally retain committed history and pending retry/compensation records through admitted storage.

## Retry state machine

A typed policy has a positive finite max_attempts (including the first), monotonic deadline, nonnegative initial/max backoff, checked arithmetic, optional bounded jitter, explicit eligible error types and cancellation. Deadline is an absolute bound on new attempts and waits, not a promise to terminate a host operation instantly. Deadline, cancellation, quota failure, panic, raise, and host-fatal failure are not automatically retryable; only matching ordinary throws and explicitly classified Result errors may retry. Exhaustion produces a typed failure containing last eligible error and attempts, preserving the declared error channel. No attempt zero; no implicit retry of an entire receive, failed panic, or a different message.

At failure, unwind attempt-local cleanup, discard speculative state and intents, release all loans and permits needed for other actors, then suspend a compiler-generated continuation on an admitted scheduler timer. Never park an OS thread or retain a critical state loan across backoff. Timer wake, cancellation and deadline are linearized by one state transition with one terminal settlement; stale generation/timer wakes do nothing. Use checked/saturating capped delay calculation; deterministic tests inject a monotonic clock and RNG, durable replay consumes the recorded delay/deadline decision rather than draws again. Durable time recovery uses a storage-admitted time anchor and fails closed if expiration cannot be established; process-monotonic timestamps are not portable.

Stable operation ID is independent of attempt number, actor activation epoch and process. Outbound idempotency key is derived from operation plus logical effect ordinal, not retry number; an ambiguous remote receipt is reconciled before any repeat without a declared safe repeat contract. Default pure/local effects are retryable; unknown external effects are rejected. Serial receive permits obey chapter 05; retry suspension does not grant an additional DATA receive to a serial actor. Reentrant actors revalidate state version on each new attempt.

## Local transactions and undo

All state reads/writes remain within compiler-validated sealed critical scopes. Atomic speculative mutations use a private write-set or exclusive bounded critical-write with a reversible log; reads never see tentative data. No suspension, external publication, escaped borrow, nested independent commit or unsafe opaque effect in the v1 local transaction. On ordinary failure/cancel, discard all changes, release resources exactly once and publish nothing; panic still goes to CONTROL after runtime cleanup where possible. If cleanup cannot prove consistency, quarantine the incarnation, never resume it.

A successful commit advances a checked monotonic version and records the operation ID. Undo/redo are authorized actor commands with expected current version and target history identity; v1 only supports linear tail undo/redo, never overwriting subsequent conflicting changes. A new ordinary commit after undo invalidates the redo branch; audit history remains append-only while retained. Inverse application is atomic, runs invariant validation and increments version even when logical state returns to earlier values. Repeated command IDs return their prior outcome without a second mutation. Missing/evicted history, stale expected version, invalid redo and unavailable capacity yield typed failures without state mutation.

Retain old values (not merely inverse arithmetic), ownership obligations and deferred destruction until no retained history references them. No escaping borrowed pointers, externally transferred unique resources, non-reversible destructors or unsupported mutation shapes in reversible regions. Reject before emission when effect/ownership proof is missing. Bounded actor history, delta bytes, deferred resources and replay work are charged to actor quota before admission; explicit retention policy may prune oldest eligible history but never silently lose a promised undo. Nonparticipating actors need not allocate history.

## Persistent actors and distributed effects

Extend the existing atomic commit_turn contract with optional journal/history, consumed command ID, retry/timer state and compensation intent metadata in the same durable transaction as state and outbox. State/version/dedup/outbox/history either all commit or none. Unknown commit outcomes must be reconciled before retry or reply; stale activation epochs cannot commit or settle. Recovery acquires fresh fencing, validates schema and version, reconstructs state and pending operations, then admits messages. Durable records hold serializable owned data, stable Symbol UUIDs and typed operation IDs, never pointers or stale capabilities. Durable replay does not resend already acknowledged effects.

A saga executes steps with stable IDs and explicit compensation contracts. Persist intent and sufficient compensation/reconciliation information before the forward effect can escape; once confirmed, settle its receipt. If the forward outcome is unknown, reconcile rather than infer success/failure. Compensate confirmed steps in reverse dependency order (LIFO for linear saga); compensate only effects requiring reversal, not speculative state already rolled back. Compensation itself is idempotent or reconciled, bounded, durable when enabled, and can fail; expose an incomplete-compensation outcome and supervisor escalation, never claim successful rollback of external state. External observations are not erased by undo; reject undo across published effects unless an explicit compensation workflow authorizes it. No automatic retry of unsafe I/O.

## Compiler/runtime handoff

Use typed policies and compiler-recognized regions/intrinsics rather than committing new reserved words now. Candidate MIR operations: tx_begin/read/write/commit/rollback; retry_begin/suspend/settle; undo_apply/redo_apply; compensation_register/settle; outbox_commit. These are conceptual operations, not stable ABI names. Model effect boundaries and explicit cleanup edges; verify no state loan crosses suspension; lower scheduler continuation and bounded journals for JVM, LLVM, Forge, .NET, Wasm, Rust, Cranelift, JS and supported real-time/HDL/Atto targets. Unsupported profiles fail with diagnostics, never silently degrade semantics. Embedded profiles require finite bounds and advertised durability availability.

Use namespaced policy symbols, e.g. #retry.exponential and #workflow.payment.pending, resolved by full declaration path and durable manifest UUID, not final segment or process address. The separate distributed-symbol proposal owns syntax and wire identity.

## Admission and existing work

Java persistent store and bounded scalar execution PRs [#1515](https://github.com/atto-lang/atto-source.java/pull/1515) and [#1523](https://github.com/atto-lang/atto-source.java/pull/1523) are prerequisites/candidates, not evidence of general undo or retry. The [checkout saga demo #9](https://github.com/atto-lang/atto-step-function-demo/pull/9) supplies application-level scenario targets, not native runtime parity. Do not duplicate these implementations; extend after exact-head review. Shared corpus belongs in atto-platform-conformance; require positive and negative compiled guests, exact source/target/toolchain, actual executed CI steps and crash/recovery receipts where claimed. Host reference models do not certify guest support.

Required cases include bounded retry/exhaustion, nonretryable effects, cancellation/wake races, rollback atomicity, tail undo/redo and conflicts, history quota, ownership restoration, unknown commit, crash before/after commit, duplicate commands, stale epochs, stable idempotency keys, ambiguous effects and compensation failure. All backend support is NOT_EXECUTED for this proposal.
