# Unified ownership capabilities and bounded fast-path checking v1

Status: PROPOSED / NOT_EXECUTED (2026-11-26). Tracks #274. This is a reconciliation amendment, not a new ownership dialect or backend certification. Existing [ownership vocabulary](ownership-vocabulary-v1.md), [shared ownership](shared-ownership-and-guards-v1.md), [owned Dyn](checked-owned-dyn-erasure-v1.md), [atomic ordering](../spec/27-atomics-and-receive-only-serialization.md), [implicit borrowing](implicit-argument-borrow-v1.md), and [field-sensitive effects](field-sensitive-borrow-effects-v1.md) remain applicable. This amendment does not admit otherwise unsupported source.

## One semantic core

Use a canonical resolved nominal TypeId, allocation/provenance root, typed place projection, rights, region/lifetime, execution domain/epoch, and checked effects. Different bindings can designate the same root. Binding mutability/rebinding, referent mutability, ownership and pointer stability are separate. A read loan does not own the allocation or increment a reference count; an exclusive loan does not gain transfer authority. No new syntax keywords are required. Ordinary nonprimitive calls retain implicit readonly loans; explicit take!, borrow! mut, share!, copy! and copy!! remain distinct. Every compiler must consume the same versioned semantic contract, not necessarily the same runtime layout.

### Type rules

- Box<T>: one affine heap owner; move transfers its owning handle without an implicit payload copy. Borrow projects the payload under the same root; no move/drop/replacement while an incompatible loan lives. Partial move/drop tracked by initialized place; do not allow partial move of a type with user-defined destructor without independently specified drop semantics. Owner identity and allocation domain survive move. Cross-domain relocation requires a separately checked allocator/lease handoff; pin is never silently broken. Box is not implicitly Copyable.
- Shared<T>: semantic frozen shared owner, scoped to its admitted domain. Existing share! semantics are unchanged. Arc<T>: candidate explicit cross-carrier atomic shared-owner representation, not a second aliasing model. It shares the readonly/frozen ordinary-data contract and trusted synchronized interior-mutability exception of Shared; no implicit coercion between representations or implied domain/ABI equality. Creating Arc from an owned value consumes the exclusive right and proves reachable freeze, domain admission and supported atomic owner retirement. Cross-thread Arc requires verified Send and Sync on T and domain admission. Ordinary borrowing Arc or Shared performs no strong retain/release; explicit sharing of a live handle creates exactly one owner, subject to count limits. A backend may elide an allocation or count operation only when lifetime, identity, cleanup and all observable effects are preserved.
- Weak<T>: non-owning allocation identity and generation, no dereference, no payload lifetime extension. upgrade returns an optional strong owner using a linearizable nonzero-strong acquisition; it cannot resurrect after last release. Payload destruction and control-block reclamation are separate. Refcounts cannot wrap or underflow. A final strong release destroys payload once on supported exits; control block remains until weak handles and runtime pins retire. Strong cycles require a documented rejection, explicit weak break or separately proven reclamation; no silent GC or leak-freedom claim. Initially disable uniqueness recovery unless an implementation can exclude all other owners, weak upgrades and live loans atomically; failure retains the original owner. Last reader is not last owner.
- Atomic<T>: only resolved supported scalar widths, initialized explicitly; it is not an arbitrary pointer, aggregate or volatile alias. seq_cst default. Strong compare_exchange failure order table: relaxed success -> relaxed; acquire -> relaxed/acquire; release -> relaxed; acq_rel -> relaxed/acquire; seq_cst -> relaxed/acquire/seq_cst. Invalid static orders reject; dynamic orders reject before the operation. Checked integer RMW overflow must not publish a wrapped update. Scalar synchronization alone cannot authorize adjacent data access. A lock-based fallback is a distinct declared target capability and not a lock-free or hard real-time claim.
- Dyn<I>: owned existential via explicit take! and independently verified nominal interface witness, distinct from borrowed dyn/interface views. Owns the erased payload with its drop/layout/domain/provenance proof. Erasure cannot manufacture Send/Sync/Sendable/Serializable or widen effect bounds. A dynamic call uses the verified interface upper bound for every possible admitted implementation (or a sound narrower closed-world proof); unknown effects conservatively overlap and cannot justify restricted calls. No default downcast or implicit boxing of borrowed values.
- Mutex<T>/RwLock<T>: only trusted guard APIs grant interior mutable access. Existing nonescaping nonsuspending guard rules apply; scheduler-safe acquisition precedes guard entry. Mutex may be Sync with Send payload; RwLock concurrent read requires Send + Sync payload. Cell<T>/RefCell<T> are local interior mutation, not Sync; moving an owned cell requires T: Send and domain admission. Pin<T> is a separate future address-stability guarantee, not Send, Sync, immortal lifetime or permission to cross await. Require physical quiescence for reclamation.

### Do not conflate a revocable region with Arc

Current host reference [runtime_capabilities_v1.rs](https://github.com/atto-lang/atto-borrow-checker.rs/blob/main/src/runtime_capabilities_v1.rs) (audited blob 03c42018330b830e5c3474ae4d03ac67e03e6e25) deliberately has a sole FrozenOwner that logically retires the region on drop even while FrozenShared handles survive. FrozenShared is a revocable read authority whose Rust Arc keeps physical storage alive, not an ordinary guest strong-owner Arc. Its weak upgrade may fail on lease contention. Preserve this separate host-region contract; do not lower guest Arc<T> to it, treat its tests as guest Arc evidence, or remove actor/supervisor revocation. Ordinary Arc strong ownership keeps its payload live until the last strong owner releases it (domain teardown is a separate explicit isolation boundary). A checked upgrade with contention-dependent failure must have a distinct contract; ordinary Weak upgrade cannot silently report a dead allocation solely because a read lease was busy. Add separate regression cases for ordinary non-final owner drop, revoked-region denial while a physical lease drains, and successful ordinary Weak upgrade while a strong owner exists without retirement.

## Capability derivation

Separate thread transfer (Send), concurrent shared access (Sync), actor transport (Sendable), wire encoding (Serializable), shallow Copyable, DeepCopyable, and relocation/Unpin. Use resolved intrinsic identity, not spelling, structural shape or an unchecked marker assertion. For ordinary products derive a capability only if all semantically relevant fields/captures and destructor/allocator constraints admit it; for sums check every possible variant. Independently verified opaque wrappers provide versioned transfer rules. No implicit Copyable from Send, Serializable from Sendable, or vice versa. Detached task/actor capture additionally requires owned payload (no nested loans, guards or thread-affine external resource) and boundary-specific domain/epoch/transfer permission. A scoped Send loan may cross only its independently checked task lifetime/physical-join boundary.

Tri-state facts: PROVEN, DENIED, UNKNOWN. Only PROVEN satisfies a required positive capability. Model type-dependency graph once per canonical type/profile; SCCs may use guarded coinductive conjunction for Send/Sync only when every member's resolved layout, edges, leaf obligations and trusted negative markers are known. Reject unguarded infinite layouts separately; no optimistic cycle bypass, unresolved edge or structural witness may prove a capability. Recursive ownership/serialization/reclamation obligations are independent. Bound nodes, edges, generic instantiations and work; exhaustion produces a deterministic diagnostic, never a permissive approximation.

## Same-pass fast checker with independent oracle

1. Intern types, projection paths and immutable effect summaries. Resolve type capabilities once per normalized instantiation/profile. Keep nominal identity and destructor/ABI metadata in keys.
2. During typed HIR/MIR construction, maintain affine initialized places, active compatible loan sets, and explicit source/effect inventory. Fast-path only a documented, equivalence-tested subset. Straight-line/no-escape local bodies can use last-use counts and indexed live-loan checks; do not scan every loan on every access. Unknown indices conservatively overlap; distinct fields only when disjointness proven. An early last-use result must include every feasible use, defer, destructor, alias and unwind.
3. Use sparse CFG liveness and MAY/MUST dataflow for branch joins, loops, partial moves and exceptional/cancellation edges. Never use union of definitely initialized places; an owner is definitely live at a join only when live on all incoming reachable paths. Conflicts with MAY-live overlapping loans reject. Edge-specific phi/loan transfer preserves provenance. A region/loan crossing a suspension needs separate pinned lifetime, isolation and cleanup proof; lexical last use alone is insufficient.
4. Reuse per-function checks only with canonical typed IR fingerprint, rule/schema/compiler versions, target/profile, resolved nominal/layout/trait witnesses, effect/drop/FFI summary digests, dependency graph and relevant source-to-MIR inventory. Changes to an imported effect, negative marker, field type, destructor or ABI invalidate consumers. Cache artifacts are not trusted proofs without validated provenance and dependency binding. No cache hit may skip required verification for an unsupported profile.
5. Keep compiler-local checks in Java/C++/C#/Rust etc.; reuse the canonical Rust library in-process where practical. No per-call external subprocess. More complex flows require the supported canonical verifier via in-process or batched daemon interface, or fail closed. Independent strict/differential mode compares admission, diagnostic family, loan and cleanup obligations; disagreement blocks publication. Validate complete typed source/CFG-to-emitted-code inventory independently of consumer assertions. Do not infer authority from a serialized boolean.
6. Check parametric generic bodies once when bounds suffice; instantiate only dependent proofs and demanded codegen specializations. Do not use type erasure to discard a required proof. Separate typecheck/borrow/IR/backend time.

## Acceptance

[Case registry](../conformance/ownership-capability-fastpath-v1.json) is a target inventory, not executable fixtures or evidence. Every case needs same-byte .atto positive/semantic-negative guest inputs where applicable, exact diagnostic mapping, runtime lifecycle/stress checks where needed, and an independently validated compiler-head/fixture/workflow/toolchain/artifact/result record. Reject before guest publication; an unrelated parser error is not an ownership pass. Distinguish NOT_EXECUTED from explicit unsupported-target rejection. Java, LLVM, .NET, Forge, Wasm, Rust, Cranelift, JS, HDL, realtime and self-hosted Atto each require their own applicable profile. Browser/HDL/non-shared-memory targets must not fake cross-carrier primitives. Portable APIs belong in .atto core/alloc/std; only allocation, atomic, scheduler and narrowly audited ABI primitives in host backends.

Reference implementation is [atto-borrow-checker.rs](https://github.com/atto-lang/atto-borrow-checker.rs): reuse existing #3/#7 and #30/#40/#42 work; Rust #371 and #509, Java #602/#964/#1017, LLVM #801/#922 are existing integration candidates, not merged or verified here. Legacy ownership/borrow/atomic contracts (#33/#57/#67/#78/#80 in historical spec) are complementary; no changes to those branches in this amendment.

### Benchmark contract

Pin Rust version, Atto compiler/head, machine, cores, memory and build profiles; identical observable workload and correctness tests. Report check-only, cold clean debug, warm incremental body edit, public signature/effect edit, and optimized executable/AOT separately. Exclude downloads and toolchain setup from steady-state timings; publish them separately. Measure at least 15 alternating paired repetitions after warmup, median/p95, peak RSS, cache hit/miss counts, analyzed functions, typed nodes, solver work and generated code size. Use many tiny callables, large generic graphs, disjoint field loans, control-flow loops, actor messages and interface dispatch; test invalidation and cold/warm acceptance equivalence. No selected-subset result implies universal superiority. Proposed targets: at most 0.50x Rust median check-only and 0.25x warm body-edit latency for matched workloads, without soundness regression. No numbers measured yet. Never disable checks or replace guest execution with host tests to improve results.
