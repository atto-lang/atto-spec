# Primitive, aggregate and object storage v1 — Java/GraalVM and LLVM candidate

Status: **TARGET / DRAFT SPECIFICATION, NOT IMPLEMENTED OR RATIFIED** (2026-11-18).
This contract describes *observable semantics* and a recommended high-performance guest representation. A Java host smoke, LLVM allocator test or source-only model is NOT proof of compiled `.atto` object support or backend parity.

## Normative direction: separate values, identity, physical storage and ownership

1. **Scalar primitives are values.** In the initial portable scalar profile, `int` is signed 64-bit, `float` is IEEE-754 binary64, and `bool` has true/false semantics. Scalar arithmetic/overflow follows the typed language rules. Scalars may be in registers, local slots, inline fields, stack frames or arrays; saying "primitives are stack allocated" is incorrect.
2. **Nominal `Struct` is a value aggregate, not a reference-identity class.** It has compiler-known declared fields in declaration order, nominal type identity, and can be flattened/embedded in locals, outer objects, arrays and continuation frames. Its physical byte layout is target-owned and checked. A struct containing owned/reference fields is NOT trivially bit-copyable; construction, moves and copies must preserve each field's ownership. Do not infer a struct's type solely from its shape.
3. **Closed `Record` is a structural aggregate.** Its canonical field/type shape is independent of source field order, though every initializer evaluates once in original source order. An open Record uses guarded shape/presence/type checks; do not mistake it for a nominal struct or ordinary Map. This follows the separate draft record/struct work (#69/#72), which must be reconciled before release.
4. **Identity-bearing `class` instances are owned objects.** Each live instance has a stable logical identity and an owner/domain, even if the optimizer scalar-replaces or stack-promotes the physical allocation. An alias is never a second owned instance. Inherited field aliases (`use Base.field as alias`) address the same storage, not copies. Static, statically linked type/layout/drop descriptors support dispatch; guest code must not depend on native vtable pointers or Java `Object` headers.
5. **`define value class` is a separate candidate category (#60):** nominal, identity-free and immutable by contract. It may be flattened like a value aggregate; never silently transform an identity-bearing class into a value class or vice versa.
6. **Built-in `String`, `Array<T>`, `List<T>` and `Map<K,V>` are not "primitive" merely because handles can fit in a machine word.** Immutable strings may use shared, properly lifetime-fenced UTF-8 backing with explicit length; conversions to Java `String` or other host types occur only at an admitted boundary. Arrays have contiguous typed element storage when required; inline scalar/struct elements and compact handles for reference elements are preferred. For `layout=soa` / `layout=aosoa(N)`, the collection layout follows the separate layout contract; nested reference aliasing and copy obligations remain unchanged. A Map retains hash/equality semantics, not Record static slots.
7. **Actor references and foreign handles are capabilities, not object-memory pointers.** `ActorRef<T>` grants only its checked messaging/lifecycle operations. Raw guest arena offsets, Java object addresses and native pointers never cross actors/tenants by casting or serialization.

## Storage/argument/ownership matrix (target)

| Category | Logical value | Recommended representation | Synchronous parameter default |
| --- | --- | --- | --- |
| `int`, `float`, `bool` | Scalar value | Unboxed i64/f64/bool; inline fields | By value |
| Reference-free `Struct` | Nominal value aggregate | Inline, flattened or stack-promoted | Verified shared loan for an ordinary nonprimitive formal; optimizer may use equivalent by-value registers |
| `Struct` / `Record` containing references | Owned/borrowed aggregate | Inline slots plus provenance-checked refs | Verified loan; no implicit reference bitcopy |
| Identity `class` | Owned object identity | Actor-local checked reference to actor heap | Verified loan; no implicit move/copy |
| Immutable value class | Identity-free nominal value | Inline or frozen backing | Verified loan by default; optimize after proof |
| `String` / collections | Typed value with ownership and storage | Inline descriptor / checked backing | Verified loan by default |
| `ActorRef<T>`, FFI capability | Revocable authority, not an object address | Versioned opaque handle | Mode-specific capability contract, NOT arbitrary guest pointer |

The proposed default argument contract is atto-spec #89. For nonprimitive `Foo`, an ordinary `fnc inspect(Foo f)` and call `inspect(foo)` establish the same checked read loan as explicit `borrow! foo`; `inspect(mut foo)` requests an exclusive writable loan when verified callee effects require it. Explicit `take!`, `copy!`, `copy!!`, `share!` and `rt share` retain distinct meanings. Unsupported or ambiguous formals fail closed: do NOT silently box, move, clone, retain, deep-copy or promote a loan. Returning an owned aggregate may use a target sret/result buffer or scalar registers; it must not return a dangling borrow.

## Layout, identity and reference ABI

- **Logical field order** is nominal declaration order for Struct; canonical field/type order for closed Record (preserve separate source initialization order); class layout follows static inheritance, visibility and alias-collision checks. Do not expose target padding/endianness through ordinary language operations.
- **Scalar codegen**: prefer `i64`/`double` for `int`/`float`. `bool` may be `i1` in SSA but its standalone in-memory ABI is a canonical 0/1 byte when byte-addressable; forbid accepting other memory values as true. Scalar slots in packed collections must follow their documented layout.
- **Object layout**: compiler-known field offsets/alignments, type ID, destructor/drop plan, ownership and allocation domain. Metadata can live in a trusted per-actor sidecar; do not mandate a per-object Java header/native pointer. Checked overflow, field bounds and alignment are mandatory before reading/writing untrusted offsets.
- **Portable guest reference target**: a 32-bit actor-local generational `Ref32` token resolved through trusted metadata into an actor-local `HeapOffset32`; zero is invalid. The 20-bit slot/12-bit generation split in atto-common-source #13 is a *candidate*, not a silently ratified ABI. A generation must never wrap into validity for a still-stale reference: retire exhausted slots or use a wider proven scheme. The ambient owner/actor incarnation is part of the validity proof even if not encoded in four bytes. Native pointers/host `MemorySegment` are NEVER serialized as guest refs.
- **Control-plane ABI nomenclature**: the distinct control reference representation is `control_generation12_slot20_v1` (12 generation + 20 slot bits), never the reversed-name draft `control_generation20_slot12_v1`; this does not reinterpret the already emitted actor references.
- **Versioned ABI boundary**: the proposed 20-bit-slot/12-bit-generation token is **`generation20_slot12`**, distinct from the hybrid actor-memory proposal's direct-offset **`offset8_plus_one`** and .NET's **`generation16_slot16`**. None are interchangeable four-byte wire formats. The separate control-loop domain uses its own typed **`ControlRef32`** handles, never actor-object references. See [control-loop and actor unmanaged memory v1](control-and-actor-unmanaged-memory-v1.md); no canonical runtime binary encoding is silently ratified by this document.
- **Crucial provenance distinction**: a four-byte Ref32 token does NOT encode its originating actor. Two actors may independently issue the same numeric token and both allocate slot 1/generation 1. Passing a token from actor A into actor B and looking it up under B's current caller context can silently alias B's own object. Therefore compiled typed IR must bind every ref use to its allocation domain and prove that a ref never enters a foreign actor's local namespace; a trusted host adapter may carry an out-of-band origin witness, but a guest-supplied origin is never trusted. Runtime generation checks alone are insufficient. This is a mandatory negative regression for Java and LLVM, not an optional defense-in-depth test.
- **LLVM transition**: the existing compact allocator (#21) uses raw four-byte `Offset32`, which alone does not prevent ABA after reuse. Limit raw offsets to compiler-proven nonescaping, pinned local access; do not expose them as unrestricted identity-class references. Integrate generational Ref32 or an equivalent versioned safety proof before claiming general object-lifetime support.
- **Representation is not the wire ABI**: native padding, field offsets and host endianness are not cross-backend wire bytes. Actor messages/network serialization must use the canonical separately versioned typed encoding. Cross-backend parity is semantic; do not require Java and LLVM to allocate byte-identical host structs.

## Java/GraalVM implementation target

- Keep primitive locals unboxed as Java `long`, `double`, `boolean`; optimize eligible small aggregates into typed locals/SSA.
- Store guest-owned identity-class graphs and nonescaping-unsafe aggregates in **per-actor off-heap arenas** (JDK FFM `Arena` / `MemorySegment`, or equivalent audited native arena). Use primitive `int` handles and checked descriptor-based load/store paths, not an automatically allocated Java wrapper per guest object, field or message. Hot-path allocations/boxing must be measured and bounded rather than assumed absent.
- The Java host may still allocate Java metadata and may be garbage-collected: label its profile **near-zero guest GC pressure**, not "the process has no GC". Epsilon Native Image zero-collection smoke does not prove stable long-run heap use.
- Scheduler carrier migration requires actor-owned lifetime management compatible with shared access: a confined arena must not be used from arbitrary carriers. An `Arena.ofShared()` is a lifetime mechanism, NOT a data-race or actor-state safety proof.
- Use compiler-emitted typed accessors and static descriptors for fields/inheritance/drop/FFI. Host interop may materialize Java objects only at an explicit, capability-checked boundary, with copy/loan and lifetime accounted for.

## LLVM implementation target

- Lower scalar values directly into typed LLVM SSA; use `alloca`/SROA for proven nonescaping value aggregates, and a bounded actor-owned heap for escaping identity objects and container storage. No guest tracing collector is needed in the strict native target.
- Resolve actor-local compact references using checked owner, generation, bounds, alignment, allocation state and type ID; then compute a temporary native address within the verified actor heap. A guest never retains the raw address beyond its proven pin/loan interval.
- Reuse the preallocated size-class/slab design where measurements justify it; no unbounded allocation paths or whole-process hard-real-time claims without actual worst-case evidence. Keep actor heap allocation, coroutine/continuation frame memory and transferable shared buffers as separate lifetime domains.
- Emit deterministic drop edges at normal/exception/raise/panic/cancellation/STOP paths. Once a STOP closes admission, wait for in-flight borrowers/pins/continuations to quiesce before reclaiming its backing storage.

## Copy, actor delivery, and suspension rules

- `copy! x` / `x.copy()` is the candidate **shallow** copy (#39): a fresh root only if nested references have verified safe sharing; otherwise reject. It is never a license to bitwise duplicate unique mutable aliases.
- `copy!! x` / `x.copy_deep()` creates an independent reachable mutable object graph (with internal alias/cycle topology preserved), using AOT-generated type-specific copy plans. Immutable backing may be shared if proven safe. No hidden deep clone on an ordinary call.
- `take! x` moves ownership logically. Across actor-private heaps, zero payload copies are allowed **only** through a generation-fenced transferable region/broker with exclusive ownership transfer and atomic mailbox admission; otherwise relocation/serialization is required, or the transfer is rejected. A failed/full send leaves the sender's ownership intact.
- `share!` and `rt share` remain explicit and cannot grant a writable alias to frozen data. Same-actor shared borrows may coexist; a mutable borrow excludes incompatible aliases. No default reference counting in ordinary function calls.
- At `await`/select, live nonescaping locals can move into a typed, actor-owned pinned continuation frame. Critical state guards and writable loans cannot silently span suspension. Native host carrier stacks are not a substitute for bounded actor-owned logical frames.

## Acceptance gates and migration

1. Reconcile atto-spec draft #89 (implicit borrowing), #39 (shallow/deep copy), #60 (value classes), #62 (eq/identity), #69/#72 (Record/Struct layouts), #82 (inherited field aliases), atto-common-source #13 (Ref32 and actor memory) and LLVM draft #21 (Offset32).
2. Specify stable, typed HIR/MIR `StorageKind`, `Place`, `Loan`, `OwnerDomain`, `RefValidity`, `DropPlan` and `LayoutPlan` facts. Keep representation-independent user semantics; make implicit allocation/boxing observable through an explicit performance profile only, never change ownership.
3. Test scalar fields/overflow, embedded nominal structs, closed/open Records, distinct class identities, aliases/inheritance, nested mutable references, shallow-copy refusal, deep-copy cycles, reference reuse/ABA, owner mismatch, actor restart, failed mailbox admission, `await` pinning, FFI escape and post-STOP use.
4. Produce **real compiled `.atto` guests** under Java JVM/GraalVM Native Image and LLVM native with exact source tree/toolchain/fixture SHAs, negative no-artifact diagnostics, sanitizer/host memory measurements and execution receipts. An allocator unit test, parsed grammar or source-free model alone is `NOT_EXECUTED` for guest support.
5. Preserve versioned compatibility for existing Java/LLVM behavior that treats bare object arguments as owned, dynamically boxes values, or currently exposes raw offsets; never silently change call/identity semantics mid-module. Missing language grammar, linked guest codegen, permissions or runtime support must return `UNSUPPORTED` or a stable diagnostic.

**Current state:** This document sets target decisions and review conditions only. Java off-heap actor pilots, LLVM compact allocator, Ref32 model and implicit borrowing/copy semantics are independently draft; no Java↔LLVM full-object conformance result is claimed.
