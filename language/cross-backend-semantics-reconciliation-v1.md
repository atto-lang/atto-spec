# Cross-backend language semantics reconciliation v1

These are the target contracts for the November 23, 2026 reconciliation. Compiler profiles can admit a verified subset and must diagnose everything outside that subset. A backend's existing behavior is evidence about that version only. Guest compatibility requires executing the same fixtures across backends.

## Control flow

- A guard executes its failure body when its condition is false. `guard condition { ... }` and `guard condition else ... end` are equivalent. Both require a boolean condition. Comma-separated checks evaluate exactly once in source order with short circuit. Every reachable failure path must return from the enclosing callable using `return` or `^`. A loop exit, exception or fallthrough cannot stand in for that return. Successful Option narrowing requires an ownership-safe proof that survives every use.
- Named functions and methods require explicit result annotations and explicit `return value` or `^ value` on each normally completing non-void path. They may fall through when declared void. A single-expression arrow lambda returns its expression. Do not synthesize callable returns from final expression statements. The caret at the beginning of a return statement has the same meaning and cleanup behavior as `return`.
- In functional `if` and `match x over`, an arm's `return value` or `^ value` supplies the construct's value and transfers to its join. Value contexts require a result on every reachable path with compatible types. A single-arm functional if can appear in statement position, where its value is discarded and a false condition has no action. To return that value from a named callable, explicitly return the entire expression. In statement context, a bare `if` with action arms such as `do y` is imperative. Explicit `do if` is always imperative, including when an arm returns. A non-void return inside `do if` targets the enclosing callable.
- `do match` and `do select` are imperative and have type `void`. Each arm may fall through or exit early with `return`, `return void`, or `^ void`. Those exits target the arm join and run arm cleanup. Reject a non-void arm return even when the enclosing callable has the same return type. This prevents a blocking selection from silently returning a value from its surrounding callable.

Related proposals: [guard](https://github.com/atto-lang/atto-spec/pull/200), [Java if variants](https://github.com/atto-lang/atto-source.java/pull/1698), [Java value match](https://github.com/atto-lang/atto-source.java/pull/1207), [Java select cleanup](https://github.com/atto-lang/atto-source.java/pull/692) and [.NET structured guard](https://github.com/atto-lang/atto-source.net/pull/202).

## Errors, macros and pipelines

- `throw!`, `raise!` and `panic!` accept values implementing `Throwable`, `Raisable` and `Panicable`, respectively. Each trait is checked independently. Built-in `Error` implements the applicable traits and its subtypes retain their identity through unwinding. An explicitly conforming non-`Error` value keeps its payload and nominal identity. An ABI may transport it in a guest error envelope that preserves that identity. A bare string is inadmissible unless its type conforms. Accept the bare keyword spellings as compatibility aliases.
- `trap!` and `trap` have the same semantics. Evaluate once and catch ordinary escaping throws. For a non-Result value of type `T`, produce `Ok(T)` on success or `Err` with the original error on failure. An existing `Result` passes through with no extra nesting. Widen its error type when necessary to admit the trapped error. An `Option` operand remains an Option inside the successful Result. Raise, panic, cancellation and host-fatal errors bypass the boundary. Postfix `?` propagates the original failure variant through callable cleanup and is independent of exceptional control.
- Use contextual `expand!` for macro expansion, following [the macro proposal](https://github.com/atto-lang/atto-spec/pull/216).
- `pipe!` and `rpipe!` are the preferred actor graph spellings. The bare spellings are aliases. Functional `|>` and `<|` remain distinct. Require typed graph admission, bounded DATA, and appropriate start, shutdown and cancellation semantics before admitting executable graph lowering.

Related proposals: [Java error admission](https://github.com/atto-lang/atto-source.java/pull/1704), [Java async trap](https://github.com/atto-lang/atto-source.java/pull/579), [Java typed propagation](https://github.com/atto-lang/atto-source.java/pull/735), [.NET guest Result gap](https://github.com/atto-lang/atto-source.net/pull/19), [Java actor pipelines](https://github.com/atto-lang/atto-source.java/pull/402) and [.NET actor pipeline stage](https://github.com/atto-lang/atto-source.net/pull/25).

## Numeric semantics

- Signed `int / int` produces an `int` truncated toward zero. For example, `5 / 2 eq 2` and `-5 / 2 eq -2`. Use explicit floating operands for IEEE division. Checked zero division and overflow (including signed minimum divided by minus one) are distinct ordinary guest errors and retain their identity through `trap!`. A backend unable to emit both error paths must reject inputs for which it cannot prove safety before emission. Integer remainder uses the named `Integer.rem` operation and carries the dividend sign. `Integer.mod` is Euclidean.
- Decimal arithmetic stays exact. A nonterminating decimal quotient such as decimal `1 / 3` requires an explicit precision and rounding context. Without it, emit the specified typed context-required outcome. Do not import a host default precision.

[Spec #209](https://github.com/atto-lang/atto-spec/pull/209) owns the numeric details and candidate error ABI. [Conformance #563](https://github.com/atto-lang/atto-platform-conformance/pull/563) owns the corresponding fixture registry. [Java #1736](https://github.com/atto-lang/atto-source.java/pull/1736) and [.NET #237](https://github.com/atto-lang/atto-source.net/pull/237) are the primary implementation follow-ups. The binary64 quotient in [.NET #191](https://github.com/atto-lang/atto-source.net/pull/191) describes the previous proposal. The floating integer-operand rule recorded in [spec #151](https://github.com/atto-lang/atto-spec/pull/151) is superseded by this target.

## Actors and tasks

- Ordinary actors permit reentrant DATA receives by default. When A suspends, B may start on its own logical stack while A remains live, within a bounded runtime-configured limit. A `serial` actor keeps exactly one live DATA receive across suspension and leaves B queued until A retires. A continuation resumes the same invocation with a fresh physical lease on an eligible worker. Physical capacity, logical receive capacity and actor-state loans remain independently enforced.
- Supervisor failure/lifecycle CONTROL has bounded reserved capacity independent of DATA. Scheduler continuations, I/O readiness and internal dispatch receipts have their own admission and wakeup rules. A FIFO-head rule for internal receipts cannot delay an authenticated terminal supervisor notification behind DATA. Fence worker tickets, replies, releases and STOP/restart by incarnation generation.
- Actor methods can borrow a known local projection such as `self.values[0]` when the checker proves the place and lifetime in an admitted state region. Use `handle_state` and `critical-read` or `critical-write` according to the needed capability. Keep the loan local to its region and turn. Reject a conflicting write, mutation that invalidates the projection, escape, or suspension with a live loan. `Array.get_copy()` returns an owned `Option<T>` for copyable `T`, using a temporary read loan through index validation and copying. Mutation after the call cannot change the returned copy.
- `sync task<T> { ... }` returns `T` inline on its caller's thread, with no scheduler task identity or future. A legal `rt cooperate` checkpoint may yield and resume on the same caller thread; an `await` or transitive effect without a proven same-thread continuation must be rejected with `E_SYNC_TASK_SUSPEND`. Do not park a carrier to simulate this guarantee. Inline cleanup and existing loan restrictions still apply. `task<T> { ... }` returns `Future<T>` and executes cooperatively under the scheduler. A suspended task can resume on a different worker. Do not promise migration or require affinity by default. Test independently scheduled tasks, ready and pending await, cancellation and exactly-once retirement separately from inline task execution.

Related work: [Java actor physical admission](https://github.com/atto-lang/atto-source.java/pull/1752), [.NET admission](https://github.com/atto-lang/atto-source.net/pull/207), [Java CONTROL routing](https://github.com/atto-lang/atto-source.java/pull/1800), [.NET internal receipts](https://github.com/atto-lang/atto-source.net/pull/158), [Java projection loans](https://github.com/atto-lang/atto-source.java/pull/1571), [.NET array copies](https://github.com/atto-lang/atto-source.net/pull/174) and [.NET task admission](https://github.com/atto-lang/atto-source.net/pull/30).

## Library and evidence boundaries

| Area | Shared contract and evidence |
| --- | --- |
| HTTP | Preserve the native Atto header and request/response metadata surface as the API candidate. Run the same status, malformed-input and size-bound fixtures through both that API and backend response policy. A response-policy helper alone does not establish the full API. [Java #1754](https://github.com/atto-lang/atto-source.java/pull/1754) · [.NET #23](https://github.com/atto-lang/atto-source.net/pull/23) |
| Process | Use the `atto.std/process` selector and explicit imported-name precedence. Runtime process creation requires authorized host capabilities, stream ownership and bounded cancellation/wait. Profiles without these facilities diagnose the capability boundary. [Java #1759](https://github.com/atto-lang/atto-source.java/pull/1759) · [.NET #210](https://github.com/atto-lang/atto-source.net/pull/210) |
| JSON and Zorde | Register each unit through the compiler's native import path. Verify malformed UTF-8, duplicate keys, canonical wire bytes, strict parsing and budget boundaries using shared guest fixtures. Source publication and host-only oracles are separate milestones. [Java #1787](https://github.com/atto-lang/atto-source.java/pull/1787) · [.NET #231](https://github.com/atto-lang/atto-source.net/pull/231) |

Pin accepted and rejected guest source blobs. For every result record the source and compiler SHA, compilation lane, runtime target, outcome and actual runner evidence. Java JVM/GraalVM execution and .NET CoreCLR execution are separate from Native Image and NativeAOT. A zero-step workflow is unexecuted. Specialized backends can report unsupported features and the diagnostic they enforce.
