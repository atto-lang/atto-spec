# Primitive names, explicit wrappers and representation v1

Status: **TARGET / DRAFT — not implemented, ratified or parity-certified** (2026-11-25). This extends [primitive/object storage](primitive-object-storage-java-llvm-v1.md), not a replacement. This is an opt-in, versioned source-profile proposal; no existing program changes meaning silently. S-23 in the legacy ledger is partially resolved by this target; interpolation grammar is still open.

## Naming and identity

Intrinsic type spellings are lowercase and exact-case. Canonical boolean is `bool`; `boolean` is a compatibility alias, normalized only after resolution proves intrinsic identity. Canonical text is `string`. The canonical registry is [primitive-type-naming-v1.json](../contracts/primitive-type-naming-v1.json). Its names do not certify width, overflow, arbitrary precision, ABI or backend implementation beyond separately adopted numeric contracts.

Named classes, actors, interfaces, enums, ADTs, generic types and declared wrappers conventionally use PascalCase; functions, methods, fields and bindings use snake_case. These are style conventions, not a new grammar restriction on user identifiers or generic parameters. Names are case-sensitive. Never case-fold, trim or apply host locale transforms to resolve types. Unicode identifier policy remains independent. A named type is resolved by declaration identity, not by spelling or initial letter. Unresolved names fail; a user-defined lowercase named type does not become an intrinsic.

Uppercase wrappers are distinct nominal standard-library types if explicitly admitted by the selected profile. Only Bool, Integer and String are initial wrapper candidates; Float and the remaining numeric wrappers are reserved for future proposal, not language keywords or globally reserved identifiers. Resolve the authenticated standard declaration before applying wrapper behavior. A local/imported type of the same spelling does not acquire intrinsic conversion privileges. Integer existing parse/utility namespaces must not silently become wrapper constructors. Unsupported wrappers/operations must diagnose before guest artifact emission.

## Explicit conversion and storage

Target syntax (not existing API claims): `Integer.new(42)`, `Bool.new(true)`, `String.new("hello")`; a resolved wrapper's `unbox()` returns its underlying value. No implicit box/unbox in assignment, arguments, returns, overload selection, generics, equality or collection insertion. Checked casts and type ascription do not implicitly convert. No automatic stringification, implicit numeric narrowing, null or host boxing. Wrapping and unwrapping preserve value semantics and obey explicit ownership and lifetime rules; exact identity-bearing vs value-wrapper category requires a separate declaration contract. Do not implement wrappers merely by aliasing a primitive. Do not mandate a heap allocation because a name is capitalized: Option, Result, Tuple, nominal value types and eligible wrapper representations may remain inline. A wrapper with observable identity must preserve that identity through optimization.

Intrinsic string is immutable Unicode text with validated UTF-8 backing, explicit byte length, no implicit normalization, and content equality. A descriptor may refer to static, owned or lifetime-checked shared/borrowed backing; a borrowed view must not outlive its owner. The primitive spelling is not a license to copy ownership or pass raw addresses across domains. String is a distinct candidate library wrapper, not automatically the host Java/.NET String. Specify view-to-owned conversion, allocation failure, byte/scalar/grapheme indexing, interpolation grammar and wire representation separately before certifying them. Legacy backends that already differentiate view and owner retain their behavior in their existing profile.

## Compatibility and rollout

Existing Java/LLVM/Rust String alias and Java/.NET Bool alias behavior must remain pinned to the old profile until migration is explicit and tested. A formatter may canonicalize an authenticated alias in that profile only when semantics and selected profile are unchanged; it must never rename a resolved wrapper or user declaration. New-profile source uses lowercase intrinsic names and distinct declared wrappers. Missing support yields an explicit unsupported result or stable compile diagnostic, not fallback to the legacy alias. Type identity and generic instantiation keys use resolved declaration identity, including module and type arguments, not text or physical layout. Host FFI mappings are separate and cannot change guest semantics.
