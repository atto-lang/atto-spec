# Named tuple / Record conversion — v1

Status: language-owner requested target; compiler and guest execution NOT_EXECUTED. Extends pair-literals-and-bindings-v3 (#299) and aggregate constructors (#246); reconcile with mixed Record entries (#306) before promotion. This does not change unresolved grouped call forms, Map/Entry semantics, or legacy profile admission.

## Syntax and shape
```atto
let Tuple t = Tuple.of(five := 5, three := "box");
let Record r = Record.of(five := 5, three := "box");
let Tuple repeated = Tuple.of(five := 5, three := "box", five := 55);
let Record first = repeated.to_record(duplicates: #first);
let Record last = repeated.to_record(duplicates=#last);
```
An adjacent := constructs a nominal string-keyed Pair<V>, including in a call argument. IDENT followed by : or = at the immediate ordinary call delimiter binds a formal parameter; both normalize to the same NamedArgument representation. Mixed separators are valid, duplicate or unknown parameters and positional arguments after named ones reject under v3. A Pair argument is positional, not named binding. Resolve intrinsic identity, not text; user-defined shadowing retains normal call semantics. Preserve nested delimiters, source spans, lexical adjacency, and ordinary expression/assignment grammar. No implicit spread or reclassification based on expected type. The formatter may preserve either named separator; it must not rewrite := into either separator.

Tuple slots retain the nominal Pair value and positional order, including repeated names and heterogeneous payload types. Ordinary positional access returns the Pair itself, not an implicitly unwrapped payload. This preserves existing Tuple/Pair semantics from #299. Candidate unique-name projection t.five returns the payload; ambiguous direct access rejects. Explicit get_first/get_last/get_all named projections are proposed convenience methods, with typed result and absent-name semantics to be finalized separately. Record.of consumes Pair payloads into unique statically named fields; the Pair name must satisfy ordinary identifier validity and be statically proved in closed-shape profiles. Duplicate record fields reject even across different input spellings. Preserve existing supported Record.of forms and empty-constructor policy. Mixed named/unnamed tuples are valid tuples but strict conversion requires all slots to be proven identifier-keyed Pair values. No implicit field names.

## Conversion
Explicit to_record() requires a closed, completely known tuple shape with valid unique keys; statically known duplicates, unproved names, mixed unnamed slots and invalid identifiers reject without an executable artifact. No silent first/last preference. Explicit to_record(duplicates: #first) and to_record(duplicates=#last) choose the first or last payload for each name in source tuple order; the same named argument grammar supports either separator for either policy. The policy must be statically known in a closed structural Record profile. Invalid policy rejects; #reject is equivalent to the default. Output field type is the selected payload's resolved type, not Any or the Pair type. Different payload types under the same key are legal for first/last selection. If static source shape is unavailable, do not synthesize a runtime structural type or claim success. A separate try_to_record() Result-based dynamic-shape API and typed collision resolver are target extensions; their exact dynamic Record representation, error variants and heterogeneous fold typing remain pending. In particular dynamic keys cannot bypass closed Record admission.
 
Record.to_tuple() produces one Pair per field with the field's name and exact payload type. Proposed ordering: declared/constructed field order when available, otherwise a documented stable canonical order (must not depend on host hash iteration). Do not promise original Tuple order after conversion unless that order is preserved by the Record representation. Record equality/type identity remains name/type structural, independent of evaluation order; physical ABI unchanged. Explicit order selection is a separate extension. No automatic conversions to nominal Struct, Map or Entry.

## Evaluation, ownership and hardening
All accepted source expressions evaluate exactly once, in written order, before parameter-slot reorder or duplicate selection; discarded duplicate values are not skipped, including effects, traps and ordinary drop obligations. Reject static errors before guest execution. Conversions of existing values do not reevaluate initializers. No allocation or partial publication on static error. For move conversion transfer selected values once and release discarded owned values exactly once; do not consume a borrowed value illegally. Shallow copy must preserve independent outer slots and transitively read-only sharing for retained nested identities on every alias, with no implicit COW. Deep copy is explicit. Preserve lifetime, mutability, contextual allocator, actor-boundary and cleanup obligations. Do not imply zero-GC proof from scalar constant folding. Compiler may eliminate intermediate Pair storage only when observable identity, effects and ownership agree. Bound shape/key work according to existing compiler limits and reject excess sizes rather than crash.
