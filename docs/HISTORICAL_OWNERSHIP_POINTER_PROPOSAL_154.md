# Historical ownership and pointer admission proposal (#154)

The November 7 candidate corrected the legacy mutable-loan spelling and proposed prohibiting all public pointer/ref/dereference intrinsics, including `Pointer<T>`. The spelling question has since been resolved by the accepted [ownership chapter](../spec/04-ownership-and-memory.md): new code uses `borrow! mut value`, and both historical `rt` orders remain migration aliases. The candidate's blanket pointer ban is historical, not an adopted amendment. The current [checked-handle call-loan profile](../language/checked-handle-call-loans-v1.md) and ownership chapter retain the separately specified checked-handle operations. Do not remove them or silently broaden their admission.

Raw addresses must never become portable wire values, and pointer capability transport across actors, tenants, isolates and networks is forbidden under current target semantics. Pointee data requires its own authorized ownership/serialization proof. Same-domain handle operations require checked provenance and lifetime. This preserves the proposal's safety objective without contradicting later language decisions. No compiler or runtime support is certified here.
