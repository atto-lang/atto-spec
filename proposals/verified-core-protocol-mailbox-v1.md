# Verified Core local protocol mailbox v1

This candidate implements live, transition-only handlers on the existing serial DATA lane. .NET emits static C# actor bindings and typed ingress for NativeAOT. Java lowers checked actor source to `ProtocolActorMir` and spawns through the code-image-bound executor. LLVM emits a host protocol artifact with `oreslang-llvmc --emit-protocol-actors` and links it to the native source actor runtime. Host integration uses the checked by-value actor identity and copies frames into bounded actor-owned storage. Guest-side spawn and send syntax is pending. ## Local DATA framing

The compiler assigns state and message ordinals in ordinal name order. It derives a 32-byte SHA-256 fingerprint from the protocol name, initial state, state names and terminal flags, message signatures, and edges. The canonical fingerprint input uses the domain string `atto.protocol.mailbox.v1`, followed by those items in that order. Counts and exponents are signed 32-bit little-endian values, signed bounds are 64-bit little-endian values, and booleans occupy one byte. Strings use UTF-8 preceded by a seven-bit continuation byte length. Lists begin with their count. Messages are in ordinal name order and their fields follow parameter order. Each field contributes its `i32` flag, inclusive lower and upper bounds, ordered dimension names and exponents, and the normalized scale numerator and denominator as decimal strings. Edges are ordered by source state and message and contribute source, message, and destination names in that order. Field binder names contribute no bytes.

Each DATA frame contains the ASCII magic `ATPM`, version byte `1`, the schema fingerprint, an unsigned 16-bit little-endian message ordinal, and exactly one signed 64-bit little-endian value per field. A generated host ingress method uses `int` for an Atto `i32` field and `long` for `int`. Values carry the units fixed by their message schema. The schema fingerprint distinguishes the expected field interpretation. The receiving runtime applies ordinary `ActorRef` incarnation authority independently.

## Dispatch and publication

An actor incarnation starts in its compiled initial state. The runtime dequeues its frames on the existing serial DATA lane. It checks the envelope, selects the edge for the current state and tag, and validates the exact byte length and inclusive signed bounds of every field. The runtime publishes the destination only while holding the actor-cell gate used by stop and authenticates the current actor turn. Illegal edges and invalid frames leave the state intact.

After dispatch the actor publishes a receipt. .NET sends it to the host-supplied reply mailbox. Java publishes it on the actor's read-only output stream, using the existing private transport's detached byte list for both inbound and outbound frames. LLVM uses a bounded readback queue on the incarnation. The native scheduler receives a slot number for a copied frame, and mailbox admission reserves capacity for its receipt. The receipt begins with ASCII `ATPR` and version byte `1`, then a runtime-local actor ordinal, incarnation generation, and turn sequence as unsigned 64-bit little-endian fields. A status byte follows, then source and destination ordinals as unsigned 16-bit little-endian fields. Status values are `1` committed, `2` illegal edge, `3` invalid payload, `4` invalid envelope, and `5` interrupted before publication. A receipt records a completed dispatch attempt. Admission alone gives no completion guarantee. Abortive stop discards queued DATA and settles its buffer ownership through the existing mailbox. Receipt publication may fail after the transition decision. For example, a Java stop can close output observation before the turn publishes its receipt.

This profile stages only the destination state. Scalar state updates, actor invariants over user fields, guest-side typed send syntax, move-only payloads, and same-logical-actor restart require further implementation. The JVM, NativeAOT, and native LLVM conformance suites exercise frame bytes, live transition receipts, stop before dequeue, concurrent stop, and rejection of old references after a fresh spawn.
